Experiment 001 · part 4 · exploratory

Does the more stimulating re-skin get more views?

Each family below is one animation published in two or more versions by USP's two seed channels, with the same audio and cuts but new colors or backgrounds. Comparing versions inside a family holds the song, animation and studio fixed, so differences in views come from the re-skin, the timing, or luck.

Not yet: the direction is there, the evidence isn't

Across {{n_fam}} families ({{n_vid}} videos), a version 10 points more saturated than its siblings gets {{lead_ratio}} the views expected for its age (95% interval {{lead_ci}}). Lightness and loudness point the same way. None of the three passes the test after correcting for testing three measures, and the placebo (cuts per minute, which re-skins share) shows a spread as wide as the real measures.

These families are the ones the pattern was first noticed on, so this run only shapes the test. The real test runs on other studios' families, with the rules fixed in advance (PLAN.md).

Publish order and the noise floor

Re-upload families (nothing changed between copies) show how much views differ by channel, timing and luck alone. Re-skin versions spread about as widely as re-uploads, so a color effect, if real, is small next to that noise.

Later versions get fewer views than the channel's typical video of their age, in re-skins and even more in re-uploads. In raw views, a later version beats its family's first in {{skin_later}} re-skins and {{upload_later}} re-uploads: the later versions that win stand out, but they're the minority. A likely reason: studios re-release their hits, so the first version is a proven success and later ones fall back toward the channel's norm.

How many families a clear answer needs

If the effects seen here are the true ones: the chance that a test on this many families finds them at Holm's strictest level (p < 0.017).

Saturation needs a few hundred families; loudness, at the size seen here, more than any search is likely to find.

All families

Versions in publish order. "vs expected" is views divided by the channel's typical views for a video released around the same time, at the same length class.

Method

  • Outcome: log views, measured against the channel's median for its other videos released within ± days in the same length class (up to 4 min, longer; compilations and family videos left out). That expected value takes age and era together, so publish order can be tested separately.
  • Model: family fixed effects; measure, later version (not the first published) and a holiday flag as terms; standard errors clustered by family.
  • Test: each measure shuffled among its family's versions times; Holm correction across the three measures. Intervals: family resamples.
  • Pairwise check: odds that the version higher on the measure has more views, per step, each family weighted once (estimate table). It ignores how much more, so it can disagree with the ratio: saturation's interval stays above 1×, loudness's points below.
  • Spread in family: the typical factor between a version's views (against expected) and its family's average.
  • Shorts (vertical downloads) are compared only with Shorts; no family mixed the two.
  • Robustness: with a window twice as wide, the ratios are .
  • Limits: features come from the dataset's clip where the video is in it, else from the pair report's shared part; views were saved by the search run on 2026-11-11 and 12. One studio only. The studio decides what to re-skin and promote, so this shows association, not cause.
